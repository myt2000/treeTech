# TechTree 中英双语化实施计划

## 目标
为项目加中英切换开关：界面文案、枚举标签、demo 剧本全部双语；1658 条技术的名称+描述提供中文翻译；tech/、fields/ 静态页输出双语版本。英文正典数据与全部质量审计链路保持不变。

## 架构决策（应对探索发现的硬约束）

1. **翻译层独立于正典数据**：新增 `data/i18n/zh.json`，结构 `{ "<tech id>": { "name": "蒸汽机", "description": "…" } }`。**不改动 data/*.json 的任何英文内容** → validate-data、时间一致性审计、质量快照、PUT 写回、trust 审计零影响。
2. **零依赖 i18n 运行时**：新增根目录 `i18n.js`（无依赖，所有页面先加载）：
   - `t(key, fallbackEn)`：中文模式查字典，否则回退英文内联值（避免把 430 条英文全抽成字典，降低回归风险）
   - `ZH_LABELS`：era / maturity / reviewStatus / edge type / evidence_level / datePrecision 等枚举的"英文键→中文显示名"映射（数据键不动）
   - `localize(tech)`：中文模式下用 zh.json 覆盖 name/description，缺失时回退英文
   - 语言开关：页头按钮「中文/EN」，localStorage 记忆，默认跟随 `navigator.language`；切换后 `location.reload()` 并更新 `<html lang>`
3. **HTML 文案**：三个页面（index/demo/sorted）约 118 处文案的元素加 `data-i18n="key"`，运行时替换文本；英文保留在标记里作兜底。
4. **JS 文案**：app.js / demo.js / sorted.js 约 115 条字面量改走 `t()`。
5. **分类标签**：sorted.js 的 branchRules / fieldRules / fieldLaneRules（~150 条）每条加 `zh` 字段；下拉 option 的 value 保持英文、显示文本用中文；所有 `item.branch === selected` 之类匹配逻辑不动。era 图例/筛选同理。
6. **demo 剧本**：storyCuts 48 条场景每条加 `titleZh` / `captionZh`（内容级翻译）。
7. **服务端**：server.js 新增只读路由 `GET /api/i18n/zh` 返回 zh.json（只读模式下可用）。
8. **静态页双语**：修改 `scripts/generate-public-site.js`，tech/、fields/ 页面嵌入双语文本块 + CSS class 切换 + 内联小脚本（localStorage 与主站共用键）；sitemap.xml、llms.txt 保持英文。重新 `npm run build:public` 全量生成，通过 check:public 的 SHA1 比对。
9. **批量翻译走 TSV**（沿用项目约定）：`data/i18n/zh-batches/<era>.tsv`（5→3 列：id、name_zh、description_zh）+ 新脚本 `scripts/import-zh-translation.js` 合并进 zh.json；新脚本 `scripts/validate-i18n.js` 校验（id 必须存在于正典数据、非空、无换行符/制表符、覆盖率报告）。npm scripts 增 `i18n:import`、`i18n:check`。

## 明确不译清单（保护审计链路）
- 技术 `id`（正则锁定）；taxonomy 的 era/branch/field 枚举键（是校验锚点 + 前端硬编码配色键）
- `region` 字段及 era 默认占位符（accuracy-risk-report 与 trust-levels 按英文原文比较）
- 来源文献标题/出版方（引用不译）
- 被锁定校验的字符串：sorted.html 的 OG description、README 质量块、llms.txt 指标行（不可见于页面正文，保留英文即可通过 check-published-metrics）
- 本版保留英文（列为后续可选批次）：dependencyEdges[].note、scopeNote、roadmap.role/rationale/blockers、dateUncertaintyNote

## 实施步骤

### 阶段 1：基础设施 + 界面中文化（一次提交）
1. 新建 `i18n.js` + 中文字典文件（UI 230 条 + 枚举映射 + demo 剧本 48 条），先建术语表 `docs/ZH_GLOSSARY.md`（统一：蒸汽机、晶体管、CRISPR、可复用运载火箭 等译法）
2. 三个 HTML 加 `data-i18n` 与语言开关按钮，`<html lang>` 动态化
3. 三个 JS 字面量替换 `t()`；枚举显示走 `label()`；编辑器表单的 value 保持英文仅标签中文化
4. server.js 加 `/api/i18n/zh` 路由
5. `generate-public-site.js` 双语模板改造
6. import/validate 脚本 + npm scripts；此阶段 zh.json 允许为空（覆盖率<100% 仅警告不阻塞，保证阶段 1 可独立合入）
7. 验证：`npm run agent:ready`、`npm test`、`npm run quality`、`npm run build:public` 后 `npm run check:public`

### 阶段 2：数据翻译（7 批，子代理并行执行）
按 era 分批，每批子代理依据术语表翻译，产出 TSV → 导入 → validate-i18n → 抽样核对：
- ancient 198 / classical 173 / medieval 158 / renaissance 148 / industrial 242 / future 238（各 1-2 个子批）
- modern 501（拆 3 个子批）
- 共约 12-16 个翻译子任务；完成后 zh.json 覆盖率 100%

### 阶段 3：收尾
- `validate-i18n` 覆盖率门槛提到 100%（可改入 quality 链）
- 全量门禁：`npm test`、`npm run quality`、`npm run coverage`
- `npm run build:public` 重新生成静态页
- 重启 `npm start`，三个页面逐个验证中英切换、图无回归
- 按 AGENTS.md 流程提交并推送

## 风险与说明
- 译文由 AI 批量翻译并经术语表统一 + 抽样核对；demo 剧本等叙事文案逐条精翻
- 静态页体积约 +40%（嵌入第二语言文本），可接受
- 数据层不触碰正典 JSON，任何阶段回滚只需删除 zh.json / 还原前端文件
- 展示层改动集中在 6 个前端文件 + 1 个生成器脚本，`agent:ready` 的变更文件检查会覆盖
